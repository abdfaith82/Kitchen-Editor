# ProKitchen & Home Designer Ultimate — Android Starter

نسخة تأسيسية قابلة للتطوير باستخدام Kotlin Views. تتضمن محرر مخطط 2D، عناصر جدران/أبواب/نوافذ/أثاث، شبكة وقياساً تقريبياً، معاينة منظور كتلي توضيحية، واستيراد/تصدير JSON وPNG.

## المتطلبات
- Android Studio حديث
- JDK 17
- Android SDK Platform 35
- اتصال إنترنت أول مرة لتنزيل Gradle dependencies

## التشغيل
1. فك ضغط الأرشيف.
2. افتح المجلد في Android Studio.
3. انتظر Gradle Sync.
4. شغّل التطبيق على جهاز Android 8.0 (API 26) أو أحدث.

## ما يعمل فعلياً في هذه النسخة
- واجهة عربية/إنجليزية مختلطة للمنتج.
- رسم جدران وخطوط أبواب ونوافذ وقطع أثاث بالسحب.
- شبكة خلفية وقياس تقريبي لطول العنصر أثناء الرسم.
- تقريب اتجاه الخطوط إلى الأفقي/العمودي وبعض الزوايا.
- حذف عنصر قريب من نقطة اللمس.
- حفظ/استيراد ملف المخطط بصيغة JSON.
- تصدير لقطة PNG من مساحة العمل.
- معاينة منظور غرفة توضيحية ثنائية الأبعاد مرسومة بمنظور، لا تمثل مشهداً 3D حقيقياً.

## غير مكتمل بعد
- معاينة 3D العامة للمخطط والجولة ما زالت توضيحية؛ عارض Filament الحقيقي متاح حاليًا لملفات GLB المستوردة.
- تحليل الصورة استكشافي للحواف فقط؛ لا يوجد نموذج AI مدرّب لاكتشاف الجدران أو الفتحات بدقة.
- لا يوجد OCR أو استنتاج هندسي موثوق من صورة واحدة.
- تصدير OBJ وGLTF ينتج blockout صندوقيًا مبسطًا، وليس الشبكات الأصلية أو مطبخًا تفصيليًا.
- لا يوجد فيديو جولة، أو undo/redo كامل، أو Path Tracing.
- القياسات الناتجة عن القوالب الافتراضية/الصورة تقريبية؛ لا تستخدم كمخطط إنشائي دون قياس وتحقق.

## الخطوة التالية المقترحة
- دمج Filament (Android) أو Unity كمحرك مشهد 3D.
- بناء نموذج بيانات هندسي واحد يربط المخطط 2D والمشهد 3D.
- إضافة OCR محلي باستخدام ML Kit Text Recognition، مع دعم العربية بحسب النموذج/الحزمة المختارة.
- إضافة تحليل السكتش عبر OpenCV كبداية، ثم نموذج رؤية حاسوبية مدرب لتصنيف الجدران والفتحات والأثاث.
- إنشاء خدمة خلفية اختيارية للرندر عالي الجودة وتوليد المشاهد من الصور.
- إضافة اختبارات وحدات، Room database، وسجل أوامر للتراجع والإعادة.

## بنية الملفات
- `model/PlanModels.kt`: نموذج المشروع وتسلسل JSON.
- `ui/PlanCanvasView.kt`: محرر المخطط ثنائي الأبعاد.
- `MainActivity.kt`: واجهة التطبيق، الاستيراد والتصدير، والمعاينات التوضيحية.


## إضافة محرك الرندر — مرحلة تأسيسية

تمت إضافة مجلد `render/`:
- `RenderProfile.kt`: تعريف أوضاع الجودة وقدرات المحرك.
- `FilamentPostProcessing.kt`: تطبيق إعدادات AO وBloom وSSR وTAA باستخدام واجهة Filament العامة.
- `RenderExportPolicy.kt`: تحديد دقات التصدير وفحص مخاطر استهلاك الذاكرة.

تمت إضافة اعتماد `com.google.android.filament:filament-android:1.56.0` إلى Gradle. هذه الإضافة لم تُدمج بعد في واجهة التطبيق الحالية ولم تُختبر عبر Gradle Sync أو تشغيل جهاز.

### ما لا تدعيه هذه المرحلة
- لا تنفذ Path Tracing أو Global Illumination كاملة.
- لا تنشئ مشهد Filament أو نماذج هندسية تلقائيًا.
- لا تنفذ تصدير 4K من المشهد بعد؛ `RenderExportPolicy` سياسة تحقق فقط.
- لا تحتوي ملفات HDR أو خامات 4K جاهزة، ولا تحسب موقع الشمس فلكيًا.
- إعدادات ما بعد المعالجة تحتاج View حقيقيًا من Filament، وقد تتفاوت الجودة والأداء حسب الجهاز وFeature Level.
- لا يوجد ضمان 60 FPS؛ ذلك يعتمد على GPU وتعقيد المشهد والدقة.

مرجع واجهة Filament: https://github.com/google/filament

## إضافة مستورد الملفات — مرحلة أولية

تمت إضافة `importer/`:
- `ImportModels.kt`: سجل الصيغ مع تصنيف القدرة الفعلية بدل مساواة الامتداد بالدعم.
- `UniversalObjectImporter.kt`: نسخ GLB والتحقق الأساسي من الترويسة، فحص إحصاءات OBJ، استيراد صور، وفك ZIP مع حدود وحماية لمسارات الأرشيف.
- `ImportPickerContract.kt`: عقد أولي لمنتقي الملفات عبر Storage Access Framework.

**تنبيه:** في النسخة الأولية، GLB يُنسخ ويفحص. راجع تحديثات مسار العارض في نهاية هذا الملف؛ ما زال البناء واختبار الجهاز مطلوبين. OBJ يُفحص هندسيًا فقط ولا يُحوّل إلى GLB. الصيغ الأخرى التي تحتاج محولات تُعلن صراحة أنها غير منفذة. التفاصيل وخارطة الطريق في `ARCHITECTURE_NEXT_STEPS_AR.md`.

## إضافات مرحلة التفاعل والاستيراد والتصدير

- سحب وحدات الأثاث في مخطط 2D مع ظل شفاف وتغذية لمسية، ومحاذاة تقريبية إلى حدود الغرفة والوحدات المجاورة ضمن 12 سم.
- إظهار المسافات التقريبية من الوحدة المحددة إلى جانبي الغرفة، ودوران 45 درجة وعكس X/Y لعناصر الأثاث في محرر 2D.
- إعدادات Live/Final، والتعرض Exposure، وخيارات دقة حتى 4K كإعدادات واجهة؛ لا تعني أن محرك الرندر الحالي ينتج صورة 4K فعلية.
- حفظ تلقائي مؤجل عبر Room، ومؤشر حالة الحفظ.
- عرض كاميرا CameraX لالتقاط صورة مرجعية للغرفة. تحويل الصورة تلقائيًا إلى مخطط يحتاج إلى وحدة رؤية حاسوبية لم تُدمج بعد.
- معاينة BOM، وتصدير PDF ملخص أولي، وتصدير OBJ هندسي مبسط للوحدات كصناديق؛ ليس تصديرًا لشبكات 3D أصلية أو GLTF.
- كتالوج أولي لخامات PBR وتصنيفاتها، وقائمة قص قطاعات ألمنيوم بخوارزمية First-Fit Decreasing وتصدير CSV.
- منتقي استيراد GLB/OBJ: GLB يُنسخ ويفحص، ثم يُفتح في نشاط عارض Filament يستخدم `ModelViewer` من `filament-utils-android`؛ يدعم تدوير الكاميرا باللمس، ودوران الجذر 45°، وعكس المحاور، وتعديل التعريض.
- كتالوج خامات أولي داخل عارض GLB يطبّق تلوينًا عبر معامل `baseColorFactor` إن كانت المادة المستوردة تعرض هذا المعامل. هذا ليس تحميلًا لملفات PBR texture مثل الخرائط normal/roughness.
- BOM قابل للتحرير: كمية وتكلفة الوحدة لكل عنصر أثاث، وتُحفظ القيم ضمن JSON المشروع ويستخدمها تقرير PDF لحساب الإجمالي.
- تصدير GLTF 2.0 بصيغة JSON مع buffer مضمّن base64 لشبكات صندوقية مبسطة لوحدات الأثاث. هذا تصدير blockout وليس نسخة من شبكة GLB المستوردة.
- تحليل صورة محلي استكشافي باستخدام تدرجات Sobel وكثافة الحواف، مع اقتراح قالب غرفة تقريبي من نسبة الصورة. لا يستنتج القياسات الحقيقية من المنظور ولا يُعد نموذج ذكاء اصطناعي.

### قيود يجب التحقق منها

لم يُجرَ بناء Gradle أو اختبار على جهاز Android في هذه البيئة لعدم توفر Gradle وAndroid SDK/`android.jar` وعدم توفر اتصال تنزيل من بيئة التنفيذ. يجب فتح المشروع في Android Studio وتنفيذ Gradle Sync ثم Build قبل الاعتماد عليه. عارض GLB والتحكم بالمجسم وتلوين المواد وملف GLTF المصدّر تحتاج اختبار تشغيل على جهاز حقيقي؛ ملفات GLTF المصدّرة تقريبية، وكتالوج الخامات لا يحتوي خرائط texture فعلية، وإعدادات الرندر لا تعني Path Tracing أو تصدير 4K حقيقي. تحليل الصورة استكشافي فقط ولا يغني عن القياس اليدوي.

## بناء APK

**مهم:** لا توجد نسخة APK مبنية ومختبرة مرفقة بهذه الحزمة حتى الآن. يلزم JDK 17 وAndroid SDK Platform 35 وGradle 8.9 واتصال بالإنترنت لتنزيل الاعتماديات أول مرة.

- Linux/macOS: شغّل `./build-apk.sh` من مجلد المشروع بعد إعداد `ANDROID_HOME` أو `ANDROID_SDK_ROOT`.
- Windows: شغّل `build-apk.bat` من Terminal بعد إعداد Android SDK وGradle.
- أو ارفع المشروع إلى GitHub، ثم افتح تبويب **Actions** وشغّل **Build Android APK**. عند نجاح البناء، نزّل artifact باسم `ProKitchenDesigner-debug-apk`.

مسار APK المتوقع بعد نجاح البناء: `app/build/outputs/apk/debug/app-debug.apk`.
